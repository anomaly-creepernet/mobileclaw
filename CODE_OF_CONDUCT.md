# Code of Conduct [中文版](CODE_OF_CONDUCT_zh.md)

## Be normal

Don't be abusive, discriminatory, or harassing. Don't spam issues or PRs. Use English or Chinese — both are fine.

## On issues and PRs

- Search existing issues before opening a new one.
- Bug reports should include reproduction steps, device model, Android version, and the model/API you're using.
- Feature requests should explain the use case, not just the feature.
- PRs should be focused — one change per PR unless they're tightly coupled.

## On LLM output

This project sends prompts to LLMs and runs the results. The LLM might say something offensive. That's the LLM, not us. If you find a systematic prompt that reliably produces harmful output, that's worth reporting, but don't open an issue just because an LLM was rude to you once.

## Enforcement

Repeated violations will result in issue/PR access being restricted. This is a small project — let's keep the signal-to-noise ratio high.
